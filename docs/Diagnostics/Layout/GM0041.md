# GM0041: Each segment in a multi-invocation fluent chain must be on its own line

| Property     | Value   |
| ------------ | ------- |
| **ID**       | GM0041  |
| **Category** | Layout  |
| **Severity** | Warning |
| **Default**  | Yes     |
| **Fixable**  | Yes     |
| **Settings** | Yes     |

## Description

In a fluent-chain expression with more than one invocation, every segment must be on its own line for clarity.

## Settings

| Parameter                            | Description                                                                                                   | Default |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------- |
| `dotnet_diagnostic.GM0041.threshold` | Minimum number of invocations in a chain required for GM0041 to report diagnostics. Must be greater than `1`. | `2`     |

```ini
dotnet_diagnostic.GM0041.threshold = 3
```

With value `3`, GM0041 reports only chains with 3 or more invocations.

## Violation

```csharp
var result = items.Where(x => x > 1).Select(x => x * 2).ToList();
```

All three segments (`.Where(...)`, `.Select(...)`, `.ToList()`) are on the same line, but the chain contains more than one invocation.

## Fix

```csharp
var result = items
    .Where(x => x > 1)
    .Select(x => x * 2)
    .ToList();
```

Each segment is now on its own line.

## Notes

- A diagnostic is reported on every segment from the first invocation segment to the end of the chain.
- A segment can include one or more property-access steps plus the next invocation (for example, `.Values.Where(...)`).
- A segment is considered to be on its own line when its leading dot is on a different line from the last token of the preceding expression.
- Chains with fewer invocations than the configured threshold do not trigger this diagnostic.
- Chains where at least one segment is already on its own line (mixed layout) are handled by GM0040, not GM0041.
- The code fix moves the affected segment to a new line, using the indentation of the nearest following segment already on its own line, or the current line's indentation plus four spaces as a fallback.
- This rule applies to chains in variable initializers, return statements, expression statements, and arrow expression clauses.
