# GM0039: Dot must be on the same line as the next identifier in fluent chains

| Property     | Value   |
| ------------ | ------- |
| **ID**       | GM0039  |
| **Category** | Layout  |
| **Severity** | Warning |
| **Default**  | Yes     |
| **Fixable**  | Yes     |

## Description

In a multi-line fluent-chain statement, the dot must be on the same line as the next identifier, not at the end of the previous line.

## Violation

```csharp
var definition = characterDefinitionRepository.
    Find(key);
```

The dot is at the end of the first line, separated from `Find` by a line break.

## Fix

```csharp
var definition = characterDefinitionRepository
    .Find(key);
```

The dot is now on the same line as the `Find` identifier on the next line.

## Notes

- A diagnostic is reported on each dot that appears at the end of a line in a fluent-chain statement.
- The code fix moves the dot to the beginning of the next line with the following identifier.
- This rule only applies to fluent-chain segments that span multiple lines.
- The rule applies to chains in variable initializers, return statements, arrow expression properties, and nested invocations.
