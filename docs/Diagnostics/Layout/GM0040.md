# GM0040: All fluent-chain segments must be on their own line if any segment is

| Property     | Value   |
| ------------ | ------- |
| **ID**       | GM0040  |
| **Category** | Layout  |
| **Severity** | Warning |
| **Default**  | Yes     |
| **Fixable**  | Yes     |
| **Settings** | No      |

## Description

In a fluent-chain statement, if one segment is written after a line break, then all the segments must be on their own line. Mixing single-line and multi-line segments in the same chain is not allowed.

## Violation

```csharp
var result = items.Where(x => x > 1)
    .ToList();
```

The `.Where(x => x > 1)` segment is on the same line as `items`, while `.ToList()` is on its own line.

```csharp
gateDefinition.UnlockingRule.Tasks.Select
(
    (taskDefinition, index) =>
    {
        return new TaskEntity(taskDefinition);
    }
)
    .ToList();
```

The `.UnlockingRule`, `.Tasks`, and `.Select(...)` segments share the first line, while `.ToList()` is on its own line.

## Fix

```csharp
var result = items
    .Where(x => x > 1)
    .ToList();
```

Each segment is now on its own line.

## Notes

- A diagnostic is reported on each segment (dot + identifier + invocation) that is not on its own line when at least one other segment in the chain is.
- A segment is considered to be on its own line when its leading dot is on a different line from the last token of the preceding expression.
- Single-line chains (all segments on the same line) do not trigger this diagnostic.
- The code fix moves the affected segment to a new line, using the indentation of the nearest segment already on its own line.
- This rule applies to chains in variable initializers, return statements, expression statements, and arrow expression clauses.
