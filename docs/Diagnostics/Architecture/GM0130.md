# GM0130: Namespace dependency violates clean architecture rules

| Property     | Value        |
| ------------ | ------------ |
| **ID**       | GM0130       |
| **Category** | Architecture |
| **Severity** | Error        |
| **Default**  | Yes          |
| **Fixable**  | No           |
| **Settings** | Yes          |

## Description

Enforces the dependency rule from Clean Architecture by preventing namespaces that match a configured **protected pattern** from referencing namespaces that match any configured **disallowed pattern**.

This rule is entirely opt-in: no diagnostics are emitted unless `dotnet_diagnostic.GM0130.rules` is configured.

## Settings

| Parameter                            | Description                                                              | Default |
| ------------------------------------ | ------------------------------------------------------------------------ | ------- |
| `dotnet_diagnostic.GM0130.rules`     | Pipe-separated (`\|`) list of dependency rules in the format `<protected pattern> -> <disallowed pattern1>, <disallowed pattern2>, ...` | (none) |

### Pattern syntax

| Pattern      | Matches                                                        |
| ------------ | -------------------------------------------------------------- |
| `*.Domain`   | Any namespace ending with `.Domain` (e.g. `MyApp.Domain`)     |
| `MyApp.*`    | Any namespace starting with `MyApp.` (e.g. `MyApp.Services`)  |
| `MyApp.Core` | Exact match only                                               |

### Example configuration

```ini
[*.cs]
dotnet_diagnostic.GM0130.severity = warning
dotnet_diagnostic.GM0130.rules = *.Domain -> *.Presentation, *.Application, *.Infrastructure
```

Multiple rules can be separated by `|`:

```ini
dotnet_diagnostic.GM0130.rules = *.Domain -> *.Presentation, *.Application, *.Infrastructure | *.Application -> *.Presentation
```

## Violation

```csharp
// .editorconfig: dotnet_diagnostic.GM0130.rules = *.Domain -> *.Application, *.Infrastructure

using MyApp.Application; // GM0130: Namespace 'MyApp.Domain' cannot depend on 'MyApp.Application'
using MyApp.Infrastructure; // GM0130: Namespace 'MyApp.Domain' cannot depend on 'MyApp.Infrastructure'

namespace MyApp.Domain
{
    class OrderRepository { }
}
```

## Fix

Remove the disallowed using directives and invert dependencies using abstractions (interfaces) defined in the domain layer:

```csharp
namespace MyApp.Domain
{
    public interface IOrderRepository { }

    class Order { }
}
```

## Notes

- The analyzer checks both file-level using directives and using directives declared inside a namespace block.
- Both regular (`namespace Foo { }`) and file-scoped (`namespace Foo;`) namespace declarations are supported.
- Only using directives are analysed — fully-qualified type references in code are not checked.
