# GM0131: Anonymous object field must have explicit name

| Property     | Value   |
| ------------ | ------- |
| **ID**       | GM0131  |
| **Category** | Style   |
| **Severity** | Warning |
| **Default**  | Yes     |
| **Fixable**  | Yes     |
| **Settings** | No      |

## Description

All fields in anonymous object creation expressions must use an explicit name assignment. Relying on the compiler-inferred name from an identifier or member access expression is not allowed.

## Violation

```csharp
class W { public string key; public string mapPrefab; }

class C
{
    void M(W[] items)
    {
        var result = System.Linq.Enumerable.Select(items, (w, index) => new
        {
            prefab = w.mapPrefab,
            w.key           // GM0131 — name 'key' is inferred, not explicit
        });
    }
}
```

## Fix

```csharp
class W { public string key; public string mapPrefab; }

class C
{
    void M(W[] items)
    {
        var result = System.Linq.Enumerable.Select(items, (w, index) => new
        {
            prefab = w.mapPrefab,
            key = w.key
        });
    }
}
```

## Notes

- The rule reports a diagnostic on the expression of any anonymous object member that lacks an explicit `name =` assignment.
- The inferred name must be derivable from a simple identifier or member access (e.g. `x`, `w.key`). Expressions from which no name can be inferred (e.g. method calls) are not reported.
- The code fix inserts the inferred name as an explicit assignment.
